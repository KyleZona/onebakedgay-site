Building onebakedgay.com on GitHub Pages

Why I left the website builder behind and hand-coded this site in plain HTML, CSS and JavaScript, hosted free on GitHub Pages.

Ky · OneBakedGayNov 17, 2026 · 3 min read

I wanted one home for everything OneBakedGay: the stream schedule, my cert progress, the home lab and the projects I'm building. The website builder I was using wanted a paid upgrade before it would run custom code, so I moved to something free that also counts as practice: writing the site myself and hosting it on GitHub Pages.

What I did

The whole site is a folder of plain files in a public GitHub repo. HTML holds the content, one shared CSS file holds the colours and fonts, and small JavaScript files handle the moving parts: the live schedule on the home page, the Windows 98 windows on the About page and the filters on Projects. Every time a change is pushed to the main branch, GitHub Pages publishes it.

ky@obg:~/onebakedgay-site$ git push origin main
To https://github.com/KyleZona/onebakedgay-site
   main -> main

What broke

The first push got a 403: I was signed in, but the app doing the push hadn't been given access to the repo yet. Authentication is proving who you are; authorization is what you're allowed to touch. Then the site itself showed a 404 until I turned Pages on under Settings → Pages and pointed it at the main branch.

A 403 means "I know who you are, and no." A 404 can just mean nothing is being served yet.

What's next

Hooking up the contact form, pointing my own domain at GitHub Pages with HTTPS, and filling these notes with home lab and cert write-ups.
